# Commit Strategy

- Each implementation ticket owns one unique branch and dedicated worktree.
- Use the exact branch and base recorded in the ticket.
- Keep commits scoped to that ticket; include its implementation, tests,
  migrations, and required documentation.
- Before committing, inspect the staged changes and exclude unrelated work.
- Commit only when the user authorizes it; report actual verification results.
- Merge or close only after user acceptance and explicit authorization.
